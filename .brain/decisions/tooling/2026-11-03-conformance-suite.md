# The conformance suite

## Context

`lint`, `index`, every other implementation of the specification and the views generated by an agent without tools ([optional tools](2026-10-28-tools-optional.md)) have to be checked against one suite. A case is a repository with a brain: a `README.md` with the manifest, and often instruction files too. Such files unpacked in the dotbrain repository would really work: Claude Code would load their `CLAUDE.md` when working in those directories.

## Decision

The conformance suite is part of the specification in `spec/conformance/`, versioned and tagged together with it. Every case is one `<case>.txtar` file: a header with the description of the case and the expected violations, one per line `<rule ID> <path>`, followed by the files of one repository, each after a line `-- <path> --`, with paths relative to its root directory. A case without violations is valid and contains up-to-date views, so `index` changes no file in it. Only the set of pairs is compared (rule ID, the path of the file the violation concerns; for a missing file, the path where it should be); messages, line numbers, order and repetitions are not part of the comparison. A case file is not detected as a brain or loaded as instructions, and the txtar format is described in a few lines that an agent applies by hand.

## Consequences

The format and the comparison are described in `spec/conformance/README.md`. A self-contained valid case gives a test for an agent: the generated views are removed from the case, the agent generates them without tools, and the result is compared with the case.

## Who decides and when

The owner of the project.
