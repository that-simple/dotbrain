# Tooling and distribution

## Markdown first

The brain is plain markdown that people read and write. Generated views and instruction files are kept by the `dotbrain` CLI, and without it by an agent following the specification; a person keeping them by hand is not a supported way of working. No feature of the framework requires the CLI ([decision](../decisions/tooling/2026-11-17-cli-keeps-generated-views.md), [overview.md](overview.md), principle 5).

## The `dotbrain` CLI

One CLI with subcommands, in TypeScript run directly by Node.js (version 24 or newer), without runtime dependencies and in one implementation ([decision](../decisions/tooling/2026-10-28-tooling-technology.md)). The code is in `tools/`, the tests in `tools/test/`. A subcommand works on one code repository and its brain in `.brain/`.

| Subcommand | What it does | State |
| --- | --- | --- |
| `lint` | Checks the brain against the validity rules of the specification ([spec/validity.md](../../spec/validity.md)): manifest, frontmatter, titles, file names, decisions, steps, required sections (through the `sections` map), `apply`, freshness of generated views, links; warns about files other than markdown and about an exceeded budget of `apply: always` rules. Exits with an error when there is a violation with the error level | ready |
| `index` | Generates the views ([spec/generated-views.md](../../spec/generated-views.md)): the decision list, the index block of the brain, the status lines of steps, the managed blocks of instruction files, the rule files of the brain and the rule files with a glob; with `--check` it only reports stale views and writes nothing | ready |
| `init` | Wizard: question by question it collects the answers of the starter template's procedure ([setup.md](setup.md)), or takes them without questions, and builds from them a valid skeleton of a brain in a code repository with instruction files for agents and a setup instruction, by which the agent finishes the work (translation, code scan, architecture draft) ([decision](../decisions/tooling/2026-11-03-init-skeleton-for-agent.md)) | ready ([step 3](../steps/03-init.md)) |
| `new` | A new step, decision or area from a template, with regeneration of the views | outside 1.0, without a plan ([decision](../decisions/repository/2026-11-17-mvp-is-1-0.md)) |
| `export` | Context package for chats ([ai-integrations.md](ai-integrations.md)) | outside 1.0, without a plan ([decision](../decisions/repository/2026-11-17-mvp-is-1-0.md)) |

`lint` reads the frontmatter and recognizes sections through the `sections` map from the manifest of the brain, so it works in every language without translations in the framework ([languages.md](languages.md)). The managed block has the contract in English in every brain, so `index` generates it and `lint` checks it in full ([decision](../decisions/agents/2026-11-17-managed-block-contract-in-english.md)). The output of `lint` works as a check in CI, in a hook of an AI tool and as a report for the periodic review ([governance.md](governance.md)). The agent runs `lint` before ending work that changed the brain when the CLI is available (rule 23 of the [contract](../../spec/agent-contract.md)); in Claude Code the `Stop` hook of the starter template enforces it, running the package of the exact version `init` wrote through `npx`, only when the brain or the instruction files have changed ([decision](../decisions/agents/2026-11-17-lint-before-end-of-work.md)).

The tools are checked by the conformance suite in `spec/conformance/` ([decision](../decisions/tooling/2026-11-03-conformance-suite.md)); the cases built from the templates are built by a script in `tools/conformance/`. The checks of this repository are types, `lint` and `index --check` on this brain, freshness of the cases built from the templates and the tests, including the test of the package; in Claude Code they are enforced by a hook ([decision](../decisions/agents/2026-11-03-brain-review-procedure.md)).

## What we distribute

- The specification (the normative document).
- The conformance suite, by which tools, other implementations and views generated by an agent are checked.
- The starter template and document templates (in English; the agent translates them).
- The agent contract and the generators of instruction files.
- The `dotbrain` CLI.
- An example: this brain.

## Channels

The framework comes out as the public repository `that-simple/dotbrain` on GitHub and the npm package `@that-simple/dotbrain` with the `dotbrain` command, without a binary; plugins and skills for AI tools are outside 1.0 ([decision](../decisions/tooling/2026-11-17-no-repository-template.md), [1.0](../decisions/repository/2026-11-17-mvp-is-1-0.md)). The repository is not a template: it documents the framework and holds the specification, with each released version at the tag `spec-v<version>`, the starter procedure and the templates; a start without tools follows the starter procedure from it, and a start with tools runs `init` from the package. The managed blocks of a brain outside this repository link to the specification at the tag of its version ([spec/README.md](../../spec/README.md)). The package contains the tools compiled to JavaScript in `dist/` and the `templates/` and `spec/` directories (the specification with the conformance suite), which the tools read at runtime, besides `LICENSE`, `README.md` and `package.json`; it has no runtime dependencies. Its first version is `1.0.0`, like the version of the specification it carries; later a release that only fixes the tools leaves the version of the specification ([decision](../decisions/model/2026-11-17-spec-version-in-semver.md)).

The build to JavaScript exists only for the package ([decision](../decisions/tooling/2026-10-28-tooling-technology.md)): a separate TypeScript configuration compiles the command and `tools/src/`, without the tests and the conformance cases script, to `dist/`, keeping the layout of `tools/`, so the paths to `templates/` and `spec/` that the tools compute relative to their file point to the root of the package. The build runs when the package is packed, and `dist/` is not in git; in this repository the tools run from the `.ts` files. A test of the package installs it from the tarball and checks that `init`, `lint` and `index` work the same as from the repository.

The whole repository, together with the specification and the templates, is under the MIT license ([decision](../decisions/tooling/2026-10-28-license.md)).
