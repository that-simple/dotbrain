# Risks

The biggest risk is not technical: it is overengineering. A framework that requires tools and conventions before anyone needs them will lose to an empty `NOTES.md` file.

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Overengineering: required tools, manifests, layers above the repository | Nobody starts, because the entry threshold is too high | The principle "the simplest thing that works"; a brain only in a code repository ([decision](decisions/model/2026-11-05-code-repository-only.md)); the MVP gate is a brain without tools; tools may not be required ([overview.md](architecture/overview.md)) |
| Growth of conventions | The brain becomes bureaucracy, people go around it | A small core (only the index and decisions are mandatory); every new convention must be applicable in this brain (dogfooding) |
| The brain drifts away from practice | Dead documentation, agents work on outdated decisions | The [agent contract](../spec/agent-contract.md) (rules 5 and 16), periodic reviews, `lint` in CI ([governance.md](architecture/governance.md)) |
| Personal data in the brain | Breach of privacy, GDPR; the brain reaches everyone with access to the repository | The brain keeps no personal data or personal notes ([agent contract](../spec/agent-contract.md), rule 19, [core-model.md](architecture/core-model.md#what-the-brain-does-not-keep)); confidential content does not go into the repository |
| Dependence on one AI tool | The framework loses its point when the tool changes | One contract, adapters from one source ([ai-integrations.md](architecture/ai-integrations.md)); in the MVP only Claude Code is checked live ([decision](decisions/agents/2026-11-17-mvp-gate-without-second-ai-tool.md)) |
| Changes of the instruction formats and APIs of AI tools | Adapters stop working | Generating adapters from one source, thin adapters |
| Mixing languages in a brain, or translations duplicating content | Discrepancies between language versions | One language per brain, keys in YAML and the heading map in the manifest ([languages.md](architecture/languages.md)) |
| Conflicts from parallel changes to the brain | Lost or contradicting decisions after merging branches | Decisions as separate ADR files with IDs without coordination, lists as generated views, the conflict rules of the [agent contract](../spec/agent-contract.md) ([core-model.md](architecture/core-model.md)) |
| A brain too big for the agent's context | The agent reads too much or too little, decisions are skipped | The index as a map, descriptions in the frontmatter of every document, one topic per file, subdirectories of decisions, `apply` rules with a glob instead of `always` ([core-model.md](architecture/core-model.md)) |
| The agent skips the contract or the rules of the brain | The agent resolves open decisions or changes the work without updating the brain, and the discrepancy goes unnoticed | The contract is instructions, not a mechanism, so it is not the only protection: a change goes through a PR to a person's review, `lint` and `index --check` check the brain independently of the agent, and a hook of the AI tool can enforce them; the review against the brain ([agent contract](../spec/agent-contract.md), rule 21), in a separate context ([decision](decisions/agents/2026-11-03-brain-review-procedure.md), [committing to the main branch](decisions/agents/2026-11-03-review-before-committing-to-main.md)); the block of rules stays short thanks to the budget of `always` rules and `apply` with a glob ([decision](decisions/agents/2026-10-28-always-rules-budget.md)) |
| Weak descriptions or outdated content of documents | The agent picks documents by misleading `description`s and confidently works on outdated decisions | `description` required in every document and checked by `lint`; one topic per file; updating the document in the same PR as the work; the quality of descriptions and agreement with practice in the periodic review ([governance.md](architecture/governance.md)) |
| Decisions concerning several repositories have no place | Shared agreements of several repositories live outside the brains or are copied | Deliberately out of scope: every repository has its own brain and may link to other repositories as to any source; the framework introduces no layer above the repository ([decision](decisions/model/2026-11-05-code-repository-only.md)) |
